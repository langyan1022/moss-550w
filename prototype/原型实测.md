## 测量口径

- **页面显示。** 使用真实的无头 Microsoft Edge。记录确认按钮的点击事件，在回执卡片和最终文字各自写入可见 DOM 后等两次 `requestAnimationFrame`。两条记录在同一浏览器时钟上相减。它近似一次屏幕绘制机会；不含显示器扫描、语音合成或播放。
- **真实写入。** 工具写入临时文件、刷新磁盘并发布到以操作 ID 命名的路径。服务读回字节，确认与用户批准的预览完全相同，才向页面推送回执。测试还读取页面所链接的文件并复算 SHA‑256。
- **可比较的样本。** 应用与模型均在同机，CPU 8 线程，上下文 4096，单并发。每个独立输入先清空模型 slot；连续对话只在该组开始时清空。这里的起点是用户批准；用户在预览上花的时间、模型在批准前解析草稿的时间另外存在。
- **功能和故障。** 普通原型没有人为写入等待。需要稳定捕获写前取消或进程中断的案例，测试专用网页进程在工具内增加 3 秒等待。真实网页客户端、真实本地 Qwen 和文件系统参与实验。功能测试不用于框架耗时排名。

复测时先在 `.` 的 PowerShell 启动 `.\chat.ps1`，待本地模型就绪，执行以下三条命令。每次运行自动产生新的目录，十轮可见时间另存为 `prototype\runs\receipt-日期时间\samples.csv`。


## 记忆如何接入

本机实例按对话 ID 隔离聊天历史。只有用户明确说“记住”或在记忆面板主动添加，MOSS 才把事实单列存入 SQLite。较小的记忆库会全部提供给模型；较大时按当前问题中的字词匹配和出现频率选取，最多 12 条、正文合计最多 900 个 UTF‑8 字节。单条最多 160 个字符、360 字节。完整记忆库仍可浏览，新问题的 `memory_ids` 可用于核对本轮实际选取了哪些事实。

这种检索适合简短的姓名、代号和偏好。只做关键词相关度排序，同义改写的召回率未建立系统性基准。删除一条长期记忆会影响之后给模型提供的事实。原来写下它的聊天内容可在历史对话中继续查阅。当前界面为本机单用户设计。

**网页故障回归 9/9 通过。** 检查了界面重连保留未发消息、记忆面板操作、多轮校验码、待批准取消、待批准重启、写前取消、写前强制结束进程、已出回执后取消和已出回执后强制结束进程。写前退出后原调用 ID 恢复为待确认；重复确认没有改变已有文件；写后退出保留已核实的文件。`九个场景与逐项结果`

**长期记忆回归使用 22 条真实记录和三个网页服务进程。** 新对话从较早的记忆取回随机校验码，普通对话临时代号保持隔离；按 ID 删除后再重启，新话题回答未知，另一条昵称仍能在用户确认后写进草稿。首次回归还发现，模型把“我保存的助手测试昵称是什么？”作为写入请求；没有文件写出。现在明确的事实疑问且没有草稿或写入要求时，本轮不向模型提供 `save_draft`。针对这项改动重跑的 12 个观察事件全部通过。`记忆实测结果` · `旧版本的误调用预览`

## 重新选择框架时要考虑的差异

**OpenAI Agents SDK 0.25.0 适合让某些工具直接结束本轮。** 与 Pydantic 同批交错测试，每种接法各 4 次，12 份草稿全部逐字正确。OpenAI 的普通接法每轮请求模型 2 次，把 `save_draft` 配置为直接结束后每轮只请求 1 次；从文件读回到 SDK 返回的中位数为 2.85 毫秒。一个跨进程审批案例在批准后执行原调用，在 29.10 毫秒内写文件、核验并返回，额外模型请求为 0。3 次执行中取消均阻止异步工具写入。其会话和运行快照保存历史与待批准动作；若要管理独立的个人事实，还需配置相应的记忆存储。[工具返回行为](https://openai.github.io/openai-agents-python/agents/#tool-use-behavior) · [审批与恢复](https://openai.github.io/openai-agents-python/human_in_the_loop/)

**LangGraph + SQLite 适合每一步都需要恢复的流程。** 上一批已验证任务从检查点恢复，以及写完文件后重放节点的行为。本次另用三个真实进程验证 `SqliteStore`：同一命名空间和键能取回随机事实，另一个用户命名空间查不到，逐条删除后再次重启，另一条记忆仍在。这里测的是存储接口；哪些话需要提取成长期事实、对话时应读取哪些内容，由图中的业务步骤决定。[LangGraph 记忆文档](https://docs.langchain.com/oss/python/langgraph/add-memory)

**Qwen-Agent 0.0.34 能在模型回复前交出工具结果。** 本地 Qwen 三次均选择 `save_draft`，逐字写对，最终都答“草稿已保存。”。如果在 SDK 交付工具结果时显示回执，比等模型完整回复提前 1.51–2.13 秒，中位 1.58 秒。工具进入前关闭同步生成器，1 次中未创建文件。工具开始后另一个线程尝试关流，2 次均收到“生成器正在执行”，随后 2 份文件都已写出。该运行入口提供调用历史；若要跨进程继续已批准的草稿，应用仍需保存批准状态、调用标识及写入结果。这组计时在 SDK 消费端进行。`运行样本` · `完整方法和来源`

**nanobot 0.4.1 更接近成品个人助手。** 它已有会话历史和工作区长期资料。官方 Dream 流程可以把整理过的聊天提炼到 `USER.md`、`memory/MEMORY.md`。本机分别验证了跨进程会话续聊，以及在独立工作区编辑持久资料后重新读取；Dream 通过模型自动提取事实的质量没有在这组样本中测量。[nanobot 0.4.1 记忆说明](https://github.com/HKUDS/nanobot/blob/v0.4.1/docs/memory.md)

**Agno 3.2.1 的原生用户记忆值得考虑。** 一组实测用了两个用户、四段不同对话、六次真实 Qwen 请求。开启自动记忆更新后，模型从第一位用户的话中提取了一个随机代号，首次回复连同记忆处理用时 111.24 秒。同用户在新会话问到它时读回正确代号，换用户就查不到；按记忆 ID 删除后再开新会话也查不到，预先存入的另一条偏好仍在。

Agno 的两次同题草稿都写对了，SQLite 跨进程批准也通过。但在两次执行中取消实验中，`acancel_run()` 均先接受取消请求，约 2 秒后普通异步工具仍然写出了文件，随后整轮才返回 `CANCELLED`。这对日后接电话、家居和办公动作有直接影响。Agno 适合希望由模型自动归纳用户事实的产品，写入类工具需要额外的提交前取消控制。[Agno 用户确认](https://docs.agno.com/hitl/user-confirmation)
