# 个人助手架构实读 · OpenClaw 和 nanobot

## OpenClaw 如何处理一条 WebChat 消息

官网导航指向 `openclaw/openclaw`。本次固定稳定版 `v2026.11.6`，GitHub 于 2026-11-19 发布（UTC），提交 `06afb10d3272`，主仓库使用 MIT 许可证。以下沿 WebChat 的文本请求阅读源码，没有启动网关、连接设备或测量它的延迟。[官网](https://openclaw.ai/) · [发布记录](https://github.com/openclaw/openclaw/releases/tag/v2026.11.6) · [许可证](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/LICENSE#L1-L21)

1. **接收。** 网页通过 WebSocket 调用网关。网关为请求确定会话、代理与客户端运行 ID，返回接收回执，在独立分发流程中把消息和取消信号送给代理。客户端据此可以分别展示“请求已接收”和实际执行进度。保存草稿还需要工具提交后的独立回执。[WebChat 入口](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/docs/concepts/architecture.md#L48-L53) · [会话与运行身份](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/src/gateway/server-methods/chat-send-input-dispatch.ts#L95-L122) · [接收回执](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/src/gateway/server-methods/chat-send-input-dispatch.ts#L552-L590) · [启动分发](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/src/gateway/server-methods/chat-send-input-dispatch.ts#L631-L650) · [进入代理](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/src/gateway/server-methods/chat-send-agent-dispatch.ts#L344-L400)
2. **决定能做什么。** 内嵌代理会对相应的工具集合应用会话策略，丢弃与可信会话身份不符的调用方群组信息。另有专用命令执行审批器。使用一次性许可时，管理器核对运行授权仍有效，再按审批记录 ID 和消费者 ID 消耗许可。这种绑定适合 MOSS 用来保护“确认这份草稿”的操作；命令审批器本身只证明命令执行的语义。[工具策略](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/src/agents/embedded-agent-runner/effective-tool-policy.ts#L28-L63) · [一次许可的消费](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/src/gateway/exec-approval-manager.ts#L638-L665)
3. **停止与重启。** 指定运行的停止请求先核验运行所有者权限，再停止目标，可保存已生成的部分回复并广播中止事件。受控关闭可为正在执行的根会话留下重启标记。下次启动给它投递一条带当前身份约束的续办消息。进程崩溃或强制终止没有这一保证，旧对话可读，副作用要查实后才可重试。[停止指定运行](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/src/gateway/server-methods/chat-abort-handler.ts#L574-L636) · [广播运行中止](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/src/gateway/chat-abort.ts#L512-L542) · [投递续办输入](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/src/gateway/session-restart-resume.ts#L479-L508) · [恢复边界](https://github.com/openclaw/openclaw/blob/06afb10d3272cc9deaf38ca6a3b7b839d5935638/docs/gateway/restart-recovery.md#L468-L480)

## nanobot 如何处理一条 Telegram 消息

本次固定 `HKUDS/nanobot` 稳定版 `v0.4.1`，2026-11-06 发布（UTC），提交 `3404fe83e22b`，主仓库使用 MIT 许可证。这里追踪普通文本进入代理，再单独核对 WebUI 的重启恢复入口。[发布记录](https://github.com/HKUDS/nanobot/releases/tag/v0.4.1) · [许可证](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/LICENSE#L1-L21)

1. **接收与串行。** Telegram 适配器把正文、发送者和聊天 ID 交给公共渠道层。公共层检查 `allowFrom` 或配对记录，构建 `InboundMessage` 并发布到总线。代理循环按会话键持锁，读取会话状态后开始处理。因此一位用户在两个聊天里的会话锁可以不同；跨会话资料另有存储范围。[Telegram 收信](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/channels/telegram/runtime.py#L2017-L2040) · [发送人规则](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/channels/base.py#L293-L309) · [渠道校验](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/channels/base.py#L328-L345) · [消息入队](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/channels/base.py#L373-L389) · [会话锁与状态](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/agent/loop.py#L1627-L1663)
2. **工具及回执。** 模型给出工具调用后，运行器先发检查点，再进入执行钩子。文件工具依工作区策略约束读写目录。执行层取得工具返回值，可在 `after_execute_tool` 收到结果，再向上层给出结构化完成状态。MOSS 可以把草稿 ID、已提交内容摘要和时间作为工具输出，在此时通知用户；发送人获准聊天和同意某一版草稿是不同的授权事项。[工具调用检查点](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/agent/runner.py#L501-L530) · [工作区边界](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/agent/tools/filesystem.py#L80-L100) · [工具执行](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/agent/tools/execution.py#L182-L199) · [完成钩子](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/agent/tools/execution.py#L218-L244)
3. **取消与恢复。** SDK 的 `RunStream.cancel()` 取消并等待当前异步任务。WebUI 恢复协调器另行检查持久化的运行阶段。已有最终输出就恢复显示，发现待执行调用或工具状态不明则标记 `tool_state_unknown` 并等待人选择。用户点“继续”需要当前恢复 ID，再将续办消息送入总线；“忽略”会结案。这段代码没有对外部存储的写入作回滚承诺。[SDK 取消](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/sdk/streaming.py#L80-L96) · [工具状态判定](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/webui/recovery.py#L355-L392) · [确认与忽略](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/webui/recovery.py#L209-L252) · [续办入队](https://github.com/HKUDS/nanobot/blob/3404fe83e22b7b2cb3edae1348ed45dd9b8ad051/nanobot/webui/recovery.py#L394-L418)

## MOSS 应采用的设计

1. **让“保存成功”来自草稿存储。** 请求入队、获得批准、草稿写入成功分别产生不同的状态。确认绑定用户、草稿操作 ID 及本次展示的内容版本。写入成功后即可显示带草稿 ID 的回执，模型的中文复述可随后追加。收到停止指令或从崩溃恢复时先按操作 ID 查回执，已有提交则展示原件，待确认则展示原确认卡。
2. **让用户记忆有可编辑的归属。** 本地 SQLite 记录用户 ID、事实 ID、内容、来源会话和更新时间。新会话按用户读取；查看和删除围绕同一事实 ID。如果开启自动提取，要能判别来源并阻止从已删除事实的旧摘要再次生成；在界面说明聊天原文与备份的保留范围。
3. **只为实际需要独立部署记忆服务。** 若 MOSS 需要多个助手共用一个持续更新的用户模型，可把长期资料的读写适配给 Honcho 这类服务，并验证每轮上传的内容与删除范围。对当前本地 Qwen 草稿场景，用户确认、执行回执与重启续办继续由本地事务记录负责。OpenClaw 的整套网关和 nanobot 的工作区共享资料都没有必要随之引入。
