# 个人助手源码对照：Hermes Agent 与 Home Assistant Assist

2026-11-20 核对官方仓库。Hermes Agent 取 2026-11-19 的提交 `9f476774`；Home Assistant Core 取发布标签 `2026.11.2` 对应的 `ff5d56b8`。下文追踪两个项目的具体代码路径。本机没有运行这两套助手、配置外部记忆服务或连接设备。时延与取消的本机实测请看 MOSS 和 Qwen-Agent 各自的运行记录。

## Hermes Agent：会话、执行事件与记忆提供方

固定提交的主仓库许可证为 MIT。[许可证](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/LICENSE)

1. **历史和执行事件有不同的寿命。** 会话库按 `session_id` 创建会话，追加包含工具调用信息的消息，支持读取历史。网关则按执行代标记进行中的工具，以工具调用 ID 跟踪开始和完成。订阅消息带序号和回放周期，客户端可补读仍在缓冲区内的事件；旧事件被淘汰后须重新取状态。MOSS 可以据此区分“SQLite 里仍待确认的任务”和“此刻正在播放的进度”。[会话消息写入与读取](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/hermes_state.py#L420-L469) · [工具开始和完成](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/gateway/session_events.py#L37-L59) · [有界回放与补读](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/gateway/session_events.py#L66-L91) · [订阅者追赶](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/gateway/session_events.py#L114-L137)
2. **批准策略有明确作用域。** 网关中终端命令、代码执行、插件升级权限和 MCP 询问共用一个等待入口；通过会话键和请求身份合并重复询问，单次许可仅给第一个调用，决策持久化由调用者负责。记忆和技能写入另有可配置的批准开关。需要暂存时，系统为写入请求生成 ID，将来源、摘要和可重放参数写入文件，再按 ID 查询或丢弃。MOSS 可以沿用“先保存提案，再批准对应的具体动作”，并明确批准策略适用的工具种类。[网关决策](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/tools/approval_gateway_wait.py#L164-L190) · [暂存和清理](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/tools/write_approval.py#L68-L130) · [按操作选择策略](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/tools/write_approval.py#L193-L221)
3. **中断信号沿运行链传播。** 硬停止设置运行状态、协调压缩提交边界，然后通知当前请求、工具工作线程与子代理。此处的提交保护针对上下文压缩。工具在信号抵达前已经写入的文件，仍须靠具体执行器判断和核实。模型端点、模型提供方、API 模式及回调是独立构造参数，换端点时可以保留会话和工具控制逻辑。[中断与子代理传播](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/agent/interrupt_control.py#L202-L270) · [代理构造参数](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/run_agent.py#L233-L278)
4. **长期记忆有独立生命周期。** 内置记忆将助手笔记和用户档案分别写入 `MEMORY.md`、`USER.md`，会话开始时取有大小限制的快照。提供方接口另外定义初始化、按问题预取、逐轮同步、专用工具、关闭和会话切换等操作。管理器聚合预取并约束外部等待；切换会话时把“提交旧会话”和“绑定新会话”的钩子放入同一个串行任务，避免将旧轮次记到新会话中；关闭时限时排空后台队列。[内置档案和快照](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/tools/memory_tool.py#L1-L8) · [提供方按轮接口](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/agent/memory_provider.py#L121-L175) · [会话钩子](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/agent/memory_provider.py#L197-L212) · [有时限的预取](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/agent/memory_manager.py#L362-L384) · [会话切换与归属](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/agent/memory_manager.py#L661-L683) · [退出](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/agent/memory_manager.py#L890-L900)
5. **替换存储会改变数据去向。** RetainDB 插件用用户与会话标识构造查询，支持通过 HTTP 查询、增加和删除，轮次结束后还可将用户和助手原文送入异步摄取队列。MOSS 若在将来增加外部提供方，配置需要逐项说明发送的是问题、用户显式记住的事实，还是整轮对话。现有 SQLite 可以作为默认实现。[远端查询和写入](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/plugins/memory/retaindb/__init__.py#L97-L158) · [按轮排队的字段](https://github.com/NousResearch/hermes-agent/blob/9f47677483d1b4de4d1a88d37b3b7ca18b18b215/plugins/memory/retaindb/__init__.py#L396-L414)

## Home Assistant Assist：语音事件、对话代理与实体控制

该发布版本的 Home Assistant Core 主仓库使用 Apache-2.0。[许可证](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/LICENSE.md)

1. **语音管线允许独立选择各段。** 管线保存唤醒词实体、STT 引擎、对话引擎和 TTS 引擎，并定义分段的开始、进度、结束与错误事件。卫星侧交给管线的是异步音频流和起止阶段。对话阶段可先匹配本地意图，未匹配时调用配置的对话代理，同时传会话 ID、设备 ID、卫星 ID 和上下文。MOSS 今后可让语音及文字共用事务入口，再将显示与播报作为不同订阅者。[管线配置与事件](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/components/assist_pipeline/models.py#L11-L60) · [卫星音频入口](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/components/assist_satellite/entity.py#L442-L456) · [本地匹配和对话代理](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/components/assist_pipeline/default_pipeline.py#L785-L831)
2. **工具结果可以先到界面。** `ChatLog` 为本地工具调用创建任务、收集结果或异常，构造带 `tool_call_id` 的结果，并发布 `CONTENT_ADDED` 事件；如果一个模型响应同时包含多项工具，这段代码按调用列表逐项等待，后一个先完成也可能稍后才通知。语音流程还将聊天增量映射为 `INTENT_PROGRESS`，WebSocket 回调逐事件发给客户端。MOSS 的“草稿已保存”可由真实写入并读回的事件显示，模型继续生成解释。[工具执行与结果发布](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/components/conversation/chat_log.py#L491-L564) · [聊天增量转为管线事件](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/components/assist_pipeline/default_pipeline.py#L636-L650) · [WebSocket 发送](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/components/assist_pipeline/websocket_api.py#L212-L225)
3. **设备暴露、逐次批准和物理执行是三个问题。** 实体暴露设置按助手和实体判定。标准 LLM 工具入口查找已提供的工具、执行并返回结果，意图工具携带调用上下文将请求发给意图处理器。该路径没有统一的持久化“等待用户确认”状态。WebSocket 退订调用运行任务的 `cancel`，超时会发布错误事件；代码没有承诺取消已发送的设备服务调用或恢复物理状态。因此未来若接设备，应由集成报告“请求已受理 / 已观察到目标状态”，确认和已发出的动作应按调用 ID 记账。[实体暴露判定](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/components/homeassistant/exposed_entities.py#L247-L271) · [允许的工具列表与调用](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/helpers/llm.py#L255-L276) · [带上下文分派意图](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/helpers/llm.py#L403-L433) · [退订及超时](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/components/assist_pipeline/websocket_api.py#L245-L266)
4. **当前语音对话的历史有过期机制。** `ChatSession` 保存会话 ID、用户 ID、占用数和更新时间，闲置超过五分钟且无人占用时参与清理。对话日志存于运行中实例的数据字典，监听会话清理并按会话 ID 移除日志。本次追踪的 Assist 管线中没有发现 Hermes 式跨会话事实提供方。这个观察仅覆盖所引调用路径，不能据此判断所有 Home Assistant 集成的能力。MOSS 的个人事实、草稿审批和短时语音会话需要各自的保留规则。[会话过期参数](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/helpers/chat_session.py#L32-L59) · [清理判定](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/helpers/chat_session.py#L100-L116) · [运行时对话表](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/components/conversation/chat_log.py#L100-L114) · [清理触发日志删除](https://github.com/home-assistant/core/blob/ff5d56b825a0fb66b03d01bc297d49e206cdaba3/homeassistant/components/conversation/chat_log.py#L165-L178)

## 留给 MOSS 的两项验证

- **记忆接口。** 在现有 SQLite 上先用“显式保存、按问题检索、列出和删除”覆盖用户日常使用。若比较新提供方，复用“旧会话结束时切换、删除后新会话查询、外部读取超时、关闭进程后重开”四个场景，同时记录送出本机的字段。这样可以分别检验事实隔离、召回和数据边界。
- **工具和设备接口。** 将提案、批准、工具开始、可核实的执行结果、模型回复各自带上同一个调用 ID。先在本地草稿继续测试执行前取消、提交后中止和新进程恢复。若测试设备，再分别测“接口返回”和“状态再次读取”，报告两者的时间差。这两套源码提供的是对照设计，本次没有测量它们的反应速度。
